# examples · 真实比赛数据集（Agent 评估集 + 内容素材）

> 用途有三，**不含模型微调**（本项目不做 fine-tune，GLM 是提示词驱动）：
> 1. **Agent 评估集**：名局 + 已知结局，校准 M2 赛后报告的分析质量（报告能不能自己发现「下半场 51-40 的攻防转折」？）
> 2. **内容营销素材**：名局战报 → 小红书/抖音图文（见 `../BUSINESS.md` 增长引擎）
> 3. **「导入真实数据」功能的测试样例**（M2 待开发）

## 当前数据

| 文件 | 比赛 | 视角 | 对账 |
|------|------|------|------|
| `nba_2016_finals_g6_cle.json` | 2016 总决赛 G6：骑士 115:101 勇士 | 骑士（胜方） | ✅ 三级对账 |
| `nba_2016_finals_g7_cle.json` | 2016 总决赛 G7：骑士 93:89 勇士（The Block 之夜） | 骑士（胜方） | ✅ 三级对账 |
| `nba_2006_kobe81_lal.json` | 2006-01-22 湖人 122:104 猛龙（Kobe 81 分） | 湖人（胜方） | ✅ 三级对账 |

**三级对账 = 每队「球员得分之和 = 四节得分之和 = 最终比分」**，由 `build_examples.py` 自动断言，任何对不上的数据不会落盘。

数据字段即本项目数据模型 v0.1（见主 README）：`us/them` 四节数组 + `stats[]`（每人 得分/篮板/助攻/失误 + 可选投篮命中/出手）。`_meta` 含来源、抓取时间与故事线标签。

## 来源与可复现性

- 数据源：**ESPN 公开 API**（`site.api.espn.com`），每份文件 `_meta.sourceUrl` 可直接溯源到原始接口。
- 重新生成：`python build_examples.py`（可传 ESPN event id 只构建单场）。
- 数据本身为公开的体育事实统计；对外分发内容时请保留来源标注。

## 为什么选这几场

1. **结局 known & 跌宕**：G7 有 The Block、Kyrie 关键三分、第三节 33-27 反超——报告应能命中这些转折点，是天然的考题。
2. **两场连败连赢相邻比赛**（G6→G7）：可测试「跨场趋势」分析（Curry G6 30 分 6 犯离场 → G7 17 分）。
3. **Kobe 81**：极端个体表现，测试 MVP 与「个人英雄主义 vs 团队平衡」类洞察。
